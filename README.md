# <p align="center"> Курсовая работа: Сервис управления рассылками</p>

##  <p align="center">Техническое задание:</p>
Создать веб-приложение на Django, которое позволяет пользователям управлять рассылками сообщений для клиентов. Приложение должно включать функциональность для создания, просмотра, редактирования и удаления рассылок, а также отправки сообщений по требованию.

##  <p align="center">Установка:</p>

1. Клонируйте репозиторий.
2. Обновите зависимости с помощью команды `poetry update`.

##  <p align="center">Запуск:</p>  

Перед запуском необходимо в шаблоне .env.sample изменить значения на актуальные. Вы должны иметь базу данных и данные для почтового сервера.
Обратите внимание: В режиме DEBUG письма не отправляются, а выводятся в консоль.  
Для запуска локального сервера введите команду в консоли `python manage.py runserver`

## <p align="center">Описание:  </p>
### <p align="center"> Проект состоит из 4 приложений, каждый из которых отвечает за свою логику.</p>

*Приложение clients:*  
-------------------------------------------------------------------------------

Реализует возможность добавлять, просматривать, редактировать и удалять получателей рассылки (клиентов).

В модели описаны следующие поля:
- Email (строка, уникальное).
- Ф. И. О. (строка).
- Комментарий (текст).
- Автор записи в БД
  
Клиентов могут просматривать, вносить изменения только авторы записи и менеджеры с разрешением: `can_view_all_clients.`

*Приложение message_sender:*  
-------------------------------------------------------------------------------
Реализует возможность добавлять, просматривать, редактировать и удалять рассылки.  

Приложение использует 2 модели: Mailing и MailingAttempt.  

В модели Mailing описаны следующие поля:
- Дата и время первой отправки (datetime).
- Дата и время окончания отправки (datetime).
- Статус (строка: 'Завершена', 'Создана', 'Запущена').
- Сообщение (внешний ключ на модель «Сообщение»).
- Получатели («многие ко многим», связь с моделью «Получатель»).
- Создатель рассылки.
- Статус отображения

Рассылку могут просматривать, вносить изменения только авторы записи и менеджеры с разрешением: `can_view_all_mailings`. Для того чтобы скрыть рассылку, нужно разрешение: `can_hide_mailing`.
Если рассылка скрывается, она с помощью функции `hide_mailing` переходит в статус 'Завершена'. Для активации служит функция `activ_mailing`.  Перед тем как выполнить команду, проверяются права доступа с помощью декоратора `@permission_required`.

Кнопки скрыть рассылку и активировать отображается только менеджерам. 

За запуск рассылки через интерфейс пользователя служит функция `start_mailing`. Она запускает рассылку, проверяя перед этим дату окончания рассылки с текущей.  

Рассылку можно запустить и через командную строку введя команду `python manage.py launch_mailing`. В таком виде команда запустит все рассылки которые имеют статус "Создана" и "Запущена". Введя параметр `-pk` и номера рассылок через пробел, можно запустить конкретные рассылки с такими же статусами.

Для каждой попытки отправки рассылки сохраняется статистика в базе данных, с помощью модели MailingAttempt.
А именно:
- Дата и время попытки (datetime).
- Статус (строка: 'Успешно', 'Не успешно').
- Ответ почтового сервера (текст).
- Рассылка (внешний ключ на модель «Рассылка»).

> Логика работы попытки рассылки:
> - Инициация отправки.  
> Попытка рассылки создается каждый раз, когда запускается процесс отправки сообщений для конкретной рассылки.
>
> - Определение получателей.  
> Список клиентов, которым должно быть отправлено сообщение, определяется из выбранных клиентов для данной рассылки.
>
> - Отправка сообщения:  
> Для каждого клиента из списка выполняется отправка письма с помощью функции send_mail() из Django. В случае успешной отправки письма создается запись в модели Попытка_рассылки  со статусом «успешно».
> В случае ошибки отправки, например из-за недоступности почтового сервера, создается запись со статусом «не успешно» и текстом ошибки в поле «Ответ почтового сервера».
> - Сбор статистики.  
> Каждая попытка отправки письма фиксируется, что позволяет отслеживать успешные и неуспешные попытки, а также общее количество попыток.
> - Анализ и отчетность.  
> Данные о попытках рассылок используются для формирования статистики и отчетности, предоставляя пользователю информацию о статусе и результатах его рассылок.

*Приложение messages_for_clients:*  
-------------------------------------------------------------------------------
Реализует возможность добавлять, просматривать, редактировать и удалять сообщения.

Использует модель Message, в ней описаны следующие поля:
- Тема письма (строка).
- Тело письма (текст).   

*Приложение users:*  
-------------------------------------------------------------------------------
Реализует систему регистрации и аутентификации пользователей. Пользователи имеют возможность зарегистрироваться на сайте, подтвердив свой email. Реализует функцию входа и выхода из системы. Есть возможность восстановления пароля через email.

Модель пользователя наследуется от модели AbstractUser. Дополнительно есть поля:
- Электронная почта.
- Номер телефона.
- Аватар.
- Страна.  

Для реализации отключения пользователей менеджерами, добавлено разрешение для модели `can_view_list_users`.
В этом же приложении реализована главная страница всего приложения и базовый шаблон от которого наследуются другие страницы.  

На главной странице отображается количество всех рассылок, количество активных рассылок (со статусом 'Запущена') и количество уникальных получателей.  

Для управления пользователями, есть отдельная страница доступная менеджерам. Менеджеры должны добавляться в группу Managers, чтобы обладать такими правами.  

*Описание ролей и прав доступа:*  

- Пользователь
    - Создание, просмотр, редактирование и удаление своих клиентов и рассылок.
    - Просмотр статистики по своим рассылкам.

- Менеджер
    - Просмотр всех клиентов и рассылок.
    - Просмотр списка пользователей сервиса.
    - Блокировка пользователей сервиса.
    - Отключение рассылок.
